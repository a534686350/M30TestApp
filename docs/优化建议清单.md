# M30TestApp.V2 优化建议清单

> 生成方式：构建验证（0 警告 0 错误）+ 三路并行代码审查（设备层/脚本引擎、ViewModel/UI、配置/数据），高严重度结论均经人工逐行核实。
> 状态标记：`[ ]` 待处理。行号以当前 main（e253a4c）为准。

## 一、总体印象

架构是健康的：Core/Wpf 分层清晰，IDevice 抽象 + SIM/HW 双后端让无硬件开发成为可能；压力主链路（稳压判定→自动恢复→人工确认升级）设计完善；全项目仅 1 处 async void 且有完整防护；无 .Result/.Wait() 死锁隐患；事件订阅均有对称退订；AppLog 的 Channel 异步批量落盘质量很高。

真正的短板集中在四类：
1. **失败静默放行**——多处异常被吞后照常产出「合格」数据；
2. **编码链路不可信**——GBK/UTF-8 混用已在仓库里留下实际乱码和补丁；
3. **UI 高频渲染最后一公里**——入队侧有批处理，消费侧却全量重排；
4. **双轨实现漂移**——同一逻辑两份拷贝已出现行为分歧。

## 二、P0：数据正确性（影响检测报告可信度，优先修复）

### [ ] P0-1 设备缺失时把 0 当有效测量值写入矩阵并标 Ok
- `src\M30TestApp.Core\TaskScript\Actions\BuiltinActions.cs:240-250`
- `double value = 0` 初值 + 两分支都可能不执行 → DMM/DAC 未连接时静默写入一列「合法的 0」，MetricsCalculator 与导出器都当真值用。
- **修法**：初值改 `double.NaN`；进入循环前检查所需设备存在性，缺失则整列 Error + Warn 日志。

### [ ] P0-2 UT 切卡回声校验失败后继续读数
- `src\M30TestApp.Core\Devices\Hw\HwDevices.cs:298-321`（320 行 `"continuing anyway"`）
- 重试 3 次全败只记 Info 就返回，可能整列 UT 数据来自上一张仍通电的板卡，CRC 合法、数值在范围内、无任何 Error 标记。
- **修法**：重试耗尽抛 `InvalidOperationException`，由 DacBatchSampler 既有 catch 转成该工位 Error 单元格。

### [ ] P0-3 探漏时单阀组异常被吞，整体仍可判「探漏通过」
- `src\M30TestApp.Core\TaskScript\Actions\BuiltinActions.cs:919-953`
- 异常组 = 未检测，但 `anyExceeded` 不置位；其余组通过即走到 965 行「探漏通过」继续测试。
- **修法**：记录 `failedGroups`，非空则走既有 `ConfirmLeakCheckExceededAsyncCore` 人工确认或直接判超限。

### [ ] P0-4 编码链路统一（三条实锤）
- `src\M30TestApp.Core\Config\SlotTable.cs:56,76`：工位对应表.csv 实际是 GBK（字节级确认 `B9 A4 CE BB`=GBK「工位」），代码按 UTF-8 读、写 UTF-8+BOM，首次保存即翻转现场文件编码。
- `src\M30TestApp.Core\Data\LegacyCsvExporter.cs:66,86`：注释说 ANSI，`Encoding.Default` 在 .NET 8 实为 UTF-8 无 BOM，与旧工具链/中文 Excel 不兼容。
- `src\M30TestApp.Core\Config\TestPlan.cs:138,139,184`：留有 mojibake 补丁（匹配 `"缁濆帇"`），说明 ini 读取端已经踩过坑且只补了几个词。
- **修法**：`IniFile.Load` / SlotTable 读入口统一做「BOM 探测 → 严格 UTF-8 失败回退 GBK」（需 `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)`）；然后删除各处乱码别名。

### [ ] P0-5 pass/fail 判定别名错位
- `src\M30TestApp.Core\Config\TestPlan.cs:129-133` + `MetricsCalculator.cs:74-83` + 两个导出器的 GetFailedMetrics
- `IsMetricEnabled` 精确键匹配，用户在 `[Metrics]` 写 `Linearity=1` 时查询 `"NL"` 不命中 → 该指标被判禁用 → **超标显示 pass 且无提示**。
- **修法**：复用 SpecLimits 的别名归一化（NL↔Linearity、PH↔PressureHysteresis、TCT↔CT）。

### [ ] P0-6 主导出路径无「文件被占用」防护
- `BuiltinActions.cs:1422,1484,1497`、`LongTermStabilityRunner.cs:111-112`、`TestCheckpoint.cs:60-63`
- Excel 开着上批结果文件时，几小时采集完成后最后一步保存 IOException → 数据丢失/整轮标失败。
- **修法**：抽 `SafeWrite`（临时文件 + File.Move，占用时自动改序号重试）；`TemplatePerformanceExporter` 已有正确的 tmp+move 写法可参照。顺带给 `TestCheckpoint.Save` 包 try/catch（它每温度点执行一次）。

### [ ] P0-7 手动页多条命令输出伪造数据冒充真实读数
- `src\M30TestApp.Wpf\ViewModels\ManualViewModel.cs:444-452,437-443,460-467,493-507,563-580`
- ReadStatus 用随机数决定「稳定/波动」、SCPI 只 Tx 不真发并伪造回包、READ_T/READ_40UA 返回随机数——产线操作员会把假值当真测量。
- **修法**：接真实设备调用；接不了就明确禁用并标注「未实现」。

## 三、P1：可靠性风险

### [ ] P1-1 SelfUpdater 升级落地脚本可致「变砖」
- `src\M30TestApp.Wpf\Services\SelfUpdater.cs:92-144` + `SettingsViewModel.cs:214-253`
- 固定等 3 秒就覆盖式解压（进程没退完即失败）；失败分支隐藏窗口 pause 永久挂起锁住目录；直接解压进安装目录无回滚；zip 无哈希校验。
- **修法**：按 PID 轮询等待退出（带总超时）→ 先解压到临时目录成功后再替换 → 失败弹可见错误窗 → 发布附 sha256 并校验。

### [ ] P1-2 VisaSession 写读事务不在锁内 + COM RCW 跨线程混用
- `src\M30TestApp.Core\Devices\Hw\HwDevices.cs:43-70,119-124,517-600`
- Write+Read 配对发生在锁外，手动页与采集并发时可命令响应错配；HwDmm 有的方法包 Task.Run 有的不包，COM 对象跨套间使用。
- **修法**：整个事务纳入 `lock (_gate)`（84 行 QueryStringWithTimeout 是正确示范）；VISA 操作统一走单一串行调度，去掉装饰性 Task.Run。

### [ ] P1-3 HwOven.QueryAsync 固定睡 100ms 后一次性读
- `src\M30TestApp.Core\Devices\Hw\HwDevices.cs:238-249`
- 响应慢于 100ms 得空串、分片到达读半帧；且不持 `_portGate`，与 Close 并发可 ObjectDisposedException。
- **修法**：参照同类 `ReadExactAsync`(366-391) 改循环读到行结束符；Query 序列入锁。

### [ ] P1-4 LTS 长跑初始化失败照样开跑
- `src\M30TestApp.Core\TaskScript\LongTermStabilityRunner.cs:116-155` vs `BuiltinActions.cs:514-581`
- 两份 InitDevices 语义相反：主流程任一失败即抛，LTS 全部 catch 后带病跑几小时。
- **修法**：抽公共 `InitDevicesAsync(ctx, ct, strict)`，LTS 至少强制压力控制器/DMM 连接成功。

### [ ] P1-5 两处阀门继电器极性相反
- `BuiltinActions.cs:1613-1626` vs `:636-663`
- 同一台 DMM 的继电器两条路径一个先 Open 后 Close、一个先 Close 后 Open，必有一处理解错误；反了会把所有非目标通道挂上总线且无报错。
- **修法**：与硬件核实后封装统一的 `SwitchToAsync(target)`。

### [ ] P1-6 UI 线程同步阻塞串口操作
- `src\M30TestApp.Wpf\ViewModels\ManualViewModel.cs:617-651,653-678`
- 烘箱串口 Open/Write/Read 在 UI 线程上下文同步执行，某些驱动上界面冻结数秒。
- **修法**：放入 Task.Run 或改 BaseStream 异步读写，贯穿 CancellationToken。

### [ ] P1-7 全局异常处理器无条件 Handled=true
- `src\M30TestApp.Wpf\App.xaml.cs:25-31`
- 渲染循环内的持续性异常会无限「弹窗→继续→再弹」，进程带病运行可能损坏测试数据。
- **修法**：连续 N 次即放行走默认崩溃流程。

### [ ] P1-8 AppLog 无滚动/上限
- `src\M30TestApp.Core\Common\AppLog.cs:36-50,100-105`
- LTS 场景 256 工位 × 多列 × 天~周级运行单日志可达 GB 级。
- **修法**：按日期/大小滚动 + 保留期清理。

### [ ] P1-9 QuickTest 采集中逐工位 Dispatcher.Invoke 同步封送 & 手动采集不可取消
- `QuickTestViewModel.cs:344-352`（Invoke 阻塞采集循环）、`ManualViewModel.cs:1485-1508`（CancellationToken.None，误触只能干等）
- **修法**：改 BeginInvoke；比照 BatchSample 增加 _sampleCts 和停止按钮。

### [ ] P1-10 QueryRelayStateAsync 布尔语义三处不一致
- `HwDevices.cs:551-553`（注释自相矛盾）、`IDevice.cs:50-51`、`SimDevices.cs:205-208`
- 换 DAQ 型号后阀状态显示与联动逻辑会全盘反转且无报警。
- **修法**：以接口文档为准统一；型号差异做成 DeviceProfile 配置项（InvertRelayLogic）。

## 四、P2：性能（256 工位实时场景）

### [ ] P2-1 日志/DataIO 渲染管线每 100ms 全量重建字符串 + TextBox 整体重排
- `ManualViewModel.cs:1545-1577`、`TestRunViewModel.cs:435-450`、`LogViewModel.cs:46-61`
- flush 时逐条 Add/RemoveAt(0)（O(n) 头删）+ string.Join 重建 2000 行 + 整串赋 Text 触发全量重排；1kHz 场景 UI 线程被打满。
- **修法**：保留 TextBox 则改 `AppendText(仅新增段)` 增量追加；溢出一次批量移除。抽公共 `UiLogBuffer` 收敛四份样板。

### [ ] P2-2 数据矩阵逐格 BeginInvoke 无合批
- `TestRunViewModel.cs:203-216`（每 CellUpdated 一次 dispatch）、`:349-354`（列存在性 Any() 线性扫描）、`ObservableConcurrentDictionary.cs:34-49`（同时发 Item[] 与 Item[key]，导致整行绑定重估）
- **修法**：CellUpdate 入队 + 30~50ms drain 批量写；列名 HashSet；只发 Item[key]。

### [ ] P2-3 DeviceBase.OpenAsync 无已连接快路径
- `src\M30TestApp.Core\Devices\DeviceBase.cs:37-53`，调用方 `DacBatchSampler.cs:59`
- 每批次反复重开设备，状态抖动多余刷 UI；中途掉线会中止整批而非按工位降级。
- **修法**：加 `if (!force && State == Connected) return true;`

### [ ] P2-4 导出的 XLSX 数值单元格全是文本
- `DataMatrix.cs:203-213`、`LongTermStabilityExporter.cs:142-153` 一律 `t="inlineStr"`
- 客户拿到手的报告在 Excel 里无法直接运算/画图。TemplatePerformanceExporter.WriteNumber(267-280) 是正确写法，照抄即可。

### [ ] P2-5 杂项小浪费
- `DacBatchSampler.cs:115`、`BuiltinActions.cs:817`：每工位重复解析设置（IniFile.Get 本是内存字典），批次开头解析一次传参；
- `ManualViewModel.cs:1161-1164`：1kHz 自动保存 StreamWriter AutoFlush=true 每样本一次刷盘，改定期 Flush；
- `TestRunView.xaml.cs:27-31`：TextChanged 强制 ScrollToEnd 导致运行中无法选中复制日志，改为仅在滚动条位于底部时自动滚。

## 六、建议修复顺序

1. **第一批（数据正确性，改动小收益大）**：P0-1/2/3（三处都是几行的修改）→ P0-5 别名归一化 → P0-4 编码统一入口。
2. **第二批（防变砖 + 占用防护）**：P1-1 SelfUpdater → P0-6 SafeWrite → P1-7 异常处理上限。
3. **第三批（设备层并发纪律）**：P1-2/1-3/1-4，一次 PR 把 VisaSession 锁策略和串口读取模式统一。
4. **第四批（性能）**：P2-1 UiLogBuffer + P2-2 矩阵合批（高频场景体感最明显）。
5. **持续项**：P3-1 测试先行 → P3-2/3-3 重构随功能迭代逐步做。
